# 复盘后的行动闭环（试用）

实质复盘指判断目标差距、效果或策略，不是每次状态轮询。track、recurring和loop已承担改善职责时，每次实质复盘按本合同选动作；只读观察不扩大权限。详细执行状态和验收仍归原任务，事项仅保留最新行动摘要及回链，不另建Action账本。

## 从判断到执行

1. 从目标和新证据确定当前瓶颈，选择一个最能改善结果或消除关键不确定性的动作；“持续关注、继续优化、明天再看”不能单独充当Action。
2. 说明动作如何影响目标、要观察的信号与最小产物、谁执行；沿已有流程与授权边界，当前可做的部分当轮执行，不把独立可做工作推到下次调度。
3. 给出实际开始、下一结果检查点和预计完成，采用项目时区；外部审核或数据成熟时刻未知则明确未知，约定合理复查点，不将估计当承诺。
4. 记录实际操作、结果与证据；未做、执行失败、等待结果和已验收分开。文档、代码、部署、自查和提交回执不能替代业务结果。复查信号到达后明确继续、调整或停止的判定；没有新信息不重复同一动作。

## 每次实质复盘的行动处置

- **执行新动作**：授权内可做则先做，再回链结果；只有建议或动作清单不能算执行。
- **继续已有动作**：先核对在途记录，指向原动作、已完成部分、剩余信号和复查条件；不重复发布、提交或请求。独立可做部分仍立即推进。
- **阻塞并推进替代**：写出具体依赖和真正未完成项，执行不依赖它的有效工作；确无替代则说明依据和恢复触发。已询问且未回复的输入不反复追问，不把沉默当批准。
- **有依据维持**：只读监测、观察窗口未到或证据支持不改时，说明理由及改变判断的触发；不能用“状态未变”豁免已承担的改善责任。有效窗口无进展时沿原[停滞重评](stagnation-reassessment.md)处理。

这是决策门，不是强制每轮新增任务或改源码。无变化的普通轮询依通知约定安静，也不生成重复日志；暂停/结束不自动恢复。一次性开发已经完成且复盘无增量，可以结束，不制造优化需求。

## 最小输出

沿用原任务格式，留下：**目标差距与证据 → 行动处置及具体动作 → 实际执行/阻塞证据 → 责任与时间 → 复查信号及后续决策**。已有在途动作只更新真实变化，不复制历史。创建/更新宿主自动化时要求读取原owner并遵守本门，不复制整份合同或创建第二个调度器。

首批实质复盘检验是否减少只测量不行动，同时观察重复操作、越权、无意义新任务与上下文成本；无净收益时收窄或撤回。
