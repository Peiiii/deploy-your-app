## 这次确认下来的内容原则

1. 目标是让读者理解产品并能访问，不是只做一篇看不出工具出处的教程。第 3 张说明 GemiGo 是网页部署工具，写清 `gemigo.io`；末页再保留入口。
2. 用户优先级：HTML → ZIP → GitHub。三种是可选来源，不是连续执行的三个步骤。先讲共同的建项目操作，再分别说明三种来源。
3. 十张图分别承担：分享网页的卡点、准备文件、产品及入口、建项目、HTML、ZIP、GitHub、复制公开 URL、实际公开页面、发布前检查。
4. 正文讲具体问题，配图讲操作与产品入口。避免功能清单、口号和每页重复总结，也不以“去广告感”为理由删掉品牌与网址。
5. 自然口吻用具体动作替代抽象说法：“点新建项目，填个名字”，不用“先给网页一个固定的项目位置”。删除“先判断，再操作”等无新增信息的总结，不编造亲测经历、客户反馈或第三方身份。
6. 公开页面能加载不代表登录、数据库、支付等功能通过；不能为凑实测擅自创建或部署生产项目。
7. 发布前核对编辑器中的正文、图数和顺序，并取得最终发布确认。只有看到成功结果才报告成功。
