## 正文草稿

我做了一个叫 GemiGo 的工具，把 AI 生成的静态网页部署成一个可以分享的链接。支持直接粘贴 HTML，也支持上传 ZIP 或导入 GitHub 仓库。

如果你已经用 AI 做出了作品集、计算器、小游戏，接下来想把它发给朋友，可以试试这条路径。

先从单个 HTML 网页开始：

① 把 AI 生成的完整 HTML 代码复制出来。
② 在 GemiGo 选择 HTML 入口，粘贴代码，按页面提示填写项目信息并提交部署。
③ 等待部署完成，打开生成的链接，检查页面和按钮是否正常，再分享出去。

这个流程里，你不用自己购买服务器、配置运行环境。部署过程中也能看到日志，出了问题可以把具体报错交给 AI 排查。

手里有项目压缩包，可以用 ZIP 入口；代码已经放在 GitHub 上，也有对应入口。不必为了发布一个单页，先把所有部署工具都学一遍。

这篇先讲静态前端：作品展示、浏览器里运行的小工具和小游戏。涉及服务端代码、数据库、支付的项目，还需要单独确认对应能力；有 API 密钥的应用，也别把密钥直接写进公开的网页代码里。

我是 GemiGo 的开发者，想把“做完一个网页，发给别人用”这一步变得更顺手。可以先拿一个不涉及敏感数据的小网页试试。

## 拍摄清单与定稿条件

- 准备一个完整 HTML 示例，确认添加、勾选和刷新后的本地保存正常。明确本地保存不等于跨设备同步。
- 录制从输入 HTML 到打开线上链接的完整操作，截取上表中的真实画面。遇到报错先解决并记录，不能用假截图替代。
- 从未登录的浏览器会话访问最终链接，检查桌面与窄屏显示。若演示手机访问，需用实际手机验证后再表述。
- 若需要写耗时，记录本次完整耗时及起止点，只表述这一次的结果。当前草稿不写“几秒上线”或成功率。
- 截图排除账号邮箱、令牌、密钥和私人项目；仅展示为帖子准备的示例。
- 发布前核对平台当时的外链和商业内容标注要求，再决定试用入口的呈现方式。产品网址供内部准备使用：https://gemigo.io 。
