# GemiGo 探索推荐：完整交付方案

日期：2026-10-03（Asia/Shanghai）。状态：方案已按实测冻结，正在完整实现与上线验收；进度以工作合同和日志为准。

## 用户目标与决策边界

用户要求 AI 自主评估最合适的可行方案，开发效率应按 AI 的高效率考虑，同时保持低运行成本、用户体验、可靠性和可维护性；接下来按一次完整交付推进。Jev 是用户提供的研究线索，不是指定技术或已确认模型。产品定位仍沿用[方向背景](../thoughts/2026-10-03-app-deployment-direction.thought.md)。

用户补充：OpenAI、Cloudflare 都是可选供应商；实验必须局部、解耦、可替换、可关闭，失败后不能留下难以清理的技术债。因此“一次完整交付”指实验能力完整，不等于全站或全部用户同时改用推荐。以下范围替代此前首页与探索列表默认推荐的建议。

采用完整混合推荐：离线作品理解与多语言向量 → 当前兴趣和近期偏好 → 多来源候选 → 向量内容排序（可切换专用模型重排） → 多样性、去重与探索 → 使用反馈。把数据准备、模型比较、实现、验证、Review 和发布组织为同一次交付，不把其中某个中间版本当作交付终点。

## 真实入口与使用链路

交付入口仅为 Web/桌面共用前端的探索全屏应用流（用户所称的视频流）。首页作品区、探索普通列表、搜索、作者页及扩展插件界面继续使用现有路径。语言、分类和手动排序的明确选择优先，搜索不因个人偏好隐藏匹配结果。此次不删除首页原有评分、不把全站目录查询改成推荐默认。

建议实验开关最初只允许探索流 20% 的合格访客进入推荐组，另外 80% 使用最近发布排序；配置默认20%，关闭时回到既有目录接口。按服务端签发的身份、实验 ID 与固定盐稳定分组，会话不因翻页、刷新或模型超时重新抽签。身份不可持久化时只保证当前会话稳定，并单独报告；用户主动改变模式后退出该次主实验分析。发布前开关保持关闭，完成工程和线上验收后按配置启用局部实验，不自动扩展到其他入口。

1. 推荐组新访客进入探索流 → 立即获得可用、多主题的作品 → 打开并体验 → 继续浏览；无需先登录或填写兴趣表单。对照组走原排序，两组记录相同口径的探索流曝光与行为。
2. 用户打开科学作品并收藏 → 后续尚未加载的内容更贴近科学兴趣，同时保留其他主题和新作品 → 已展示内容位置保持稳定，返回时不会跳动。
3. 用户反馈“不感兴趣” → 该作品立即从后续推荐排除 → 清除推荐偏好后恢复无历史推荐；再次访问可延续近期偏好。登录与匿名两种状态有明确的数据归属，尊重 Do Not Track，身份不可用时使用会话内偏好。
4. 模型超时、限流或预算耗尽 → 用同一候选池的内容匹配排序继续服务 → 页面可浏览；诊断可辨认原因，不把回退称为模型成功。

## 现状与 owner

- `ExploreService` 与 `projectRepository.queryExplorePage` 已拥有公开目录筛选、分页和作品状态；继续作为目录与排序入口。
- 首页当前取热度候选并在前端按名称/描述评分、首行作者分散；探索页固定 recent。本次保持这些路径；仅探索流实验入口显式调用推荐模块。实验分流在探索流边界发生，通用目录服务不识别和推断用户兴趣。
- `MetadataService` / `aiService` 已有描述、分类、标签生成；`APP_CONTENT` 是渲染文本提取的既有服务绑定。复用内容与元信息路径，推荐分析结果不覆盖作者原始名称、描述和设置。
- 主站产品事件目前不能完整表达作品曝光、跳过、推荐批次等事实；应用 PV/UV 统计也不是实际使用或推荐用户画像。推荐事件单独定义语义，不改变现有 PV/UV 口径，不串联独立应用的访客身份。
- 实测快照546个公开Live应用；566是较早分析快照，服务实时读取公开状态。

## 技术选择

### 作品理解与候选生成

复用已有平台AI生成的作品元信息，并在索引时补入可取得的公开HTML可见文本；未知难度、年龄或体验效果保持未知。无法提取足够内容的作品只使用已知元信息，不声称已经质量验证。明显占位、内容不足、语言不适合等因素影响推荐，不自动下架作品。

多语言向量比较 Cloudflare `@cf/baai/bge-m3` 与 OpenAI `text-embedding-3-large`；后者在当前目录规模的首次索引费用约 0.074 美元，不能仅为节省数美分排除潜在质量收益。BGE-M3 是接入现有 Workers 较简单的基准，最终按中英文真实目录的召回质量、延迟与整体复杂度选择一个模型。公开作品首次建索引及内容版本变化时更新，保留来源版本、分析版本和 embedding 模型版本；正常浏览复用向量，不重复分析作品。向量和推荐特征放在推荐模块拥有的附加 D1 表，以既有作品 ID 关联，不给主目录增加实验必填状态；只缓存紧凑的公开索引，当前规模用有界向量扫描，实施性能验证确认 CPU/内存预算。索引准备不能阻断部署成功，失败可有界重试，更新完成前旧结果明确为旧版本。

候选合并兴趣相似、相邻主题、质量信号较好、新作品及少量探索来源；最多 40 个。硬条件先过滤，排序结果交付前再次核对公开、Live、未删除和当前 URL，缓存不能使私密/下架作品继续曝光。新用户按质量信号和多样性生成候选；近期访问量仅为弱信号，不能把站外流量当成全站兴趣。

### 最终模型排序

排序比较三个真实选项：Cloudflare `@cf/baai/bge-reranker-base` 的文本相关性、Jev 的闭集判断、OpenAI 低成本生成模型的结构化排序（计价示例为 `gpt-5.6-luna`）。现有平台 AI 可作为作品理解的复用路径，不为本实验迁移全平台 AI。专用 reranker 衡量兴趣描述与作品内容的相关性，不是已训练的点击预测器；Jev 也不是拿来即有用户偏好的推荐系统。三者都需要本模块的候选、行为、去重与确定性规则。

一次交付内比较至少 30 个中英文及混合语言兴趣场景，包括新用户、明确兴趣、兴趣切换、少数主题、无相关候选、重复内容；候选集合和内容版本固定，评判先基于实际作品标注，不能让被比较模型给自己打分。比较相关性、前五项不可用/明显不适合比例、多样性、选项顺序扰动稳定性、token 费用及重复请求延迟分布。合成场景证明机制，不证明真实留存。

选型规则：先满足相关性、中文质量、可用性、等待与预算门槛，在预算内选择质量最好的方案；质量相当时选择费用、延迟与接入复杂度较低者。任一模型只有带来稳定且有实质意义的质量优势才承担额外成本。差异不明时选择较简单的专用排序方案。实验发布只启用一个排序模型；记录确切版本，替代模型不成为按次投机调用或永久多模型并行系统。最终选择和证据在本文件补齐，未实测前不声称任何模型已胜出。

用户历史转换为精简的近期主题和作品行为，不发送邮箱、账号 ID、私有作品、完整访问日志。模型只判断相关性，时间衰减、权重、硬过滤和预算计算由代码完成。概率作为排序信号，不展示为真实点击/喜好概率。候选长度有界，作者内容作为数据而非指令，验证对抗性文案和候选顺序偏差。

### 用户偏好与反馈

会话兴趣优先、近期偏好补充；强信号为收藏及“不感兴趣”，打开是较弱信号，滑过和停留只是辅助。曝光只计实际可见作品；预取/缩略图/隐藏页不算曝光。模型没有每次行为都调用的必要，兴趣实质变化或候选批次变化时才生成后续批次。

匿名身份由服务端签发，不允许请求任意读写他人画像；登录偏好由现有认证确定。匿名与登录偏好分别归属，不自动合并；现有登录session确定账号归属。用户可清除近期偏好；Do Not Track 或禁持久存储时不建立持久画像，仍可正常发现作品。近期行为保留 35 天，过期清理复用现有 cron；精简偏好可由这些行为重建，避免两个独立画像真相。

推荐事件携带作品 ID、动作、推荐批次、来源和必要时长，验证大小、频率、事件幂等和身份归属；与旧产品统计共享必要基础设施但不混淆口径。预览/打开不命名为学习完成、实际游玩完成；此轮不要求任意作者应用接入 SDK 才可推荐。

### 稳定性与可维护性

推荐批次拥有固定候选快照和分页游标，避免兴趣更新使已看内容重复或消失；用户动作影响下一批。失效作品动态剔除，旧游标、索引更新、刷新、重试和偏好清除都要验证。个人结果不进入公共响应缓存，浏览器缓存按身份、筛选和偏好版本隔离，登出清理；响应使用 private/no-store 等适用策略。

保留现有明确筛选语义，recent/popularity 调用合同继续成立。探索流推荐使用显式实验请求合同（由局部 endpoint/模块承接），贯通实际前端请求、后端验证和响应；不把 recommended 注入所有目录消费者。前端只获得作品、游标和可观测批次信息，不依赖供应商名称、原始概率或 token 格式。

只增加承担推荐特征、事件/批次与模型请求真实职责的局部模块。目录权限和状态仍归现有 owner；避免通用推荐平台、供应商动态路由、额外微服务、Redis 或独立向量数据库。批次与预算的状态集中在推荐模块，首页不接入。

### 可替换与可退出的实验合同

- 局部结构为探索流接入点 → 实验分组 → 推荐模块 → 既有目录读取；推荐模块内部只有作品特征/向量与候选排序两个实际替换边界。模型适配层把供应商返回转换为作品 ID 顺序、模型版本、usage/估算费用和失败原因，不把不可比较的原始分数假装统一成点击概率。无需插件注册中心或通用框架。
- 选型脚本保留必要对照适配；线上只配置一个活动排序器。替换排序器主要修改适配实现和版本配置，不修改 UI、事件、画像或作品表。更换 embedding 需要按新维度/版本完整重建索引；新旧向量不可混算，新索引就绪前保持旧版本或回退，这是可插拔的真实边界。
- 推荐索引、偏好、事件、批次及预算表均归推荐模块；不改作者内容、不改发布成功合同、不把实验分析同步挂在每次部署上。附加迁移不重写主目录；索引任务读取现有公开目录或内容变化，推荐关闭时停止新分析与新模型调用。
- 一个总开关同时控制探索流推荐接入、推荐模型调用与新增索引工作；关闭后新请求走原排序，不读取推荐依赖。已预取的推荐队列在客户端获知关闭后丢弃，替换为原排序队列并保持当前作品，不让关闭触发当前画面跳动。开关变更的传播时限和真实浏览器行为必须验证。
- 关闭实验保留必要的只读历史结果供复盘，行为按 35 天 TTL 清理，不继续收集实验行为或产生后台 AI 费用。永久退出时按已有数据保留约定清理模块表、删除接入点/任务/绑定，单独迁移移除附加表；不需要修复主目录数据。交付提供具体退出清单和关闭演练证据。

### 实验价值判定

同一次交付包含稳定分组、对照事件、实际模型费用/回退/延迟记录与可运行的汇总查询，不建设独立实验平台。每个曝光批次记录实验组、算法/内容版本；模型回退计入其原分配组，不挑选成功请求夸大效果。

主要观察有效曝光后打开可用作品的比例、每次会话打开的不同作品数、收藏/负反馈比例与回访；配合加载失败、重复内容、首批/连续浏览等待和每千次推荐费用。停留不是实际游玩或学习成效，不以总刷屏时长单独证明产品价值。A/B 两组使用相同事件口径与语言/新老访客分层，报告人数、事件数及不确定性；当前流量不足时结论必须是证据不足，不能拿合成测试或几次收藏宣称留存提升。具体最小有价值增益与样本量在实施前按基线登记；本轮未有相应样本，不自动全站推广。

## 费用与等待合同

默认建议新增推荐 AI 月预算 10 美元、首次索引/选型总预算 5 美元；是方案工程默认值，不是用户给定的数额。涵盖新增作品分析、embedding、排序、重试与测试调用；原有平台 AI 业务费用和数据库/Workers 费用分别列示，不宣称总账单为 10 美元。实施前核对实际供应商单价与计费规则，付费套餐升级或外部准入缺口需明确报告。

模型请求设置输入上限和调用频率，预算在发请求前按保守费用原子预留，并发不可突破；按实际 usage 结算，失败但计费情况不明时不擅自退还。浏览每一项不触发一次 AI，不同时调用三个模型。预算到顶继续使用内容匹配，不取消个性化和浏览能力；观测分别记录模型成功、回退、延迟及费用。

公开价格（2026-10-03 查阅）：BGE-M3 0.0118 美元/百万输入 token；BGE reranker 模型页 0.00311 美元/百万输入 token（总价格页显示为四舍五入的 0.003）；Jev 0.042 美元/百万输入 token、输出免费；OpenAI embedding-3-small/large 分别 0.02/0.13 美元/百万输入 token；GPT-5.6 Luna 输入 0.20、输出 1.20 美元/百万 token。供应商与角色独立选型，embedding 不等于在线排序。

以下仅为模型费用估算，不含基础设施、截图/文本提取、重试、缓存折扣或免费额度，不是实际账单或等质效果比较：

| 场景 | Cloudflare | OpenAI / Jev |
| --- | --- | --- |
| 566 作品 × 每件 1,000 输入 token，仅首次 embedding | BGE-M3 约 $0.0067 | OpenAI small 约 $0.0113；large 约 $0.0736 |
| 566 作品 × 3,000 输入 + 300 输出 token，文本概要 | 复用现有模型另计，不假定免费 | Luna 约 $0.54，显式关闭推理，无工具调用 |
| 10,000 次实际排序调用，每次合计 6,000 计费输入 token | BGE reranker 约 $0.19 | Jev 约 $2.52；Luna 加每次 200 输出 token约 $14.40，显式关闭推理，无工具调用 |

Reranker 的兴趣 query 可能按每个候选对重复计费；上表 6,000 是总计费 token 假设，不能只按 JSON 请求长度估算。各模型编码和输入格式不同，真实比较以供应商 usage/账单为准。若每次推荐组访问平均 3 次模型调用，上表在线费用乘 3；若全站 10,000 次访问只有 20% 进入本入口推荐组，再乘实际合格访问占比，不把全站 PV 直接当推荐调用次数。Cloudflare 托管模型有每日 10,000 neurons 免费额度，与其他 Workers AI 使用共享；无需免费额度也应满足预算，第三方供应商模型不据此推断免费。预算高于用量时仍通过批次复用和频率控制维持低成本。

性能建议门槛：已准备索引和推荐缓存的探索接口 p95 ≤ 500ms；冷模型分支最多等待 1.2s 后采用内容排序，端到端可用结果 p95 ≤ 1.8s。使用生产 Workers 区域、代表性中英文输入和相同目录重复请求测量；浏览器记录首批可用和连续滑动表现。未达到则在本次交付内优化，不能以模型宣传值替代。界面提前获取下一批，不重排正在看的内容。

## 一次性交付验收

- R1：仅推荐组探索全屏流获得推荐；对照组、首页、探索列表、搜索和其他入口继续走原路径，不能意外产生推荐模型调用；语言/分类/手动排序继续成立。
- R2：当前会话偏好、跨访问近期偏好、收藏与不感兴趣、兴趣切换与清除偏好可操作且正确；匿名、登录、退出、Do Not Track 有明确行为。
- R3：候选多样性、近期去重、新作品曝光和稳定分页成立；更新、改私密、下架、删除后不会越过公开权限。
- R4：实际曝光/打开/收藏/负反馈可追踪到作品和批次；预取不计曝光、不把加载失败当厌恶、不伪称完成或实际学习效果。
- R5：中英文固定场景模型比较完成、选型证据与版本落盘；线上生产模型真实调用成功，并证明可控失败时继续可用。
- R6：有界内容分析/索引、缓存、并发预算、异常/限流/预算耗尽和实际费用核对通过；等待门槛有代表性重复测量。
- R7：匿名/他人画像访问隔离，身份缓存不串用，模型不收到敏感身份与私有内容，内容注入不绕过确定性过滤。
- R8：适用类型检查、lint/build、目录/推荐/真实浏览器回归、diff-only 可维护性检查或项目不存在时等价 Review，通过后精确提交、普通推送、主工作区 master 同步、部署 Web/API/实际影响目标并线上验收。最终 fetch 与远程实际 SHA、master...origin/master=0 0 全部核对。

## 执行细化与方案 Review（2026-10-03）

工作入口为 `docs/work/2026-10-03-explore-recommendation/current-state.md`，active contract 沿用 R1–R10。真实 API 探针：Cloudflare BGE 可用，Jev 经 Cloudflare 返回 402 未充值；本地 OpenAI 密钥不存在，既有网关配置为 DashScope，本地 DashScope 密钥返回 401。供应商可选，选型以可调用方案与实测基准为准，未调用方案不捏造质量结论。

最小完整落地路径：探索流专属 manager/store → POST `/api/v1/explore-feed` → 推荐模块（设置、身份、候选/索引、排序、批次、事件与预算）→ 既有目录 owner。普通列表原 manager 不变。新模块数据库前缀 `explore_rec_`，使用附加 migration，代码不在主目录写入实验状态。

身份合同：服务端 HMAC 签发随机匿名身份 token，客户端请求在 JSON body 带 token；登录身份由现有 session 解析，token绑定登录状态，切换账号/退出后重签，不能用请求传来的 user ID 越权。匿名与登录偏好各自归属，不自动合并，UI说明当前身份；DNT/关闭偏好存储时只保留内存会话兴趣、无持久行为采集。近期有效行为35天，批次2小时，曝光/打开/加载/收藏/不感兴趣各语义独立；事件以服务器批次中作品集合校验，幂等ID和大小/速率有界。

设置合同：单个D1设置行控制enabled、实验版本、分组比例、活动排序器、索引版本和月预算；运维命令经新增 scoped secret 或已有管理员session调用局部运维 endpoint。总开关关闭时，前端≤30秒/下一请求获知并抛弃未来队列，保留当前项目，返回旧目录路径；cron与运维索引停止新增AI。关闭时允许清理过期实验数据，不允许继续采集和调用模型。token签名 secret不出响应与日志，运维请求严格限定此模块操作。

候选与批次合同：公共候选通过既有目录的硬过滤与语言/分类/搜索/tag owner，新增轻投影只排除HTML源码等重字段，最多1,500件、最多40个排序候选。兴趣由最近打开/收藏/负反馈作品向量加权、会话兴趣优先；不每次访问调用生成模型总结画像。索引版本/内容hash一致才混算，使用失效或缺失索引时以元信息内容匹配回退；交付前再次公共过滤。固定批次按12项分页，游标绑定identity/筛选hash，下一批排除近2小时实际曝光和当前流已加载集合；取消的初始化请求不消耗作品。负反馈在交付下一页和下一批时屏蔽，画像变化不重排已看作品。

预算合同：每次BGE输入以UTF-8字节上界、候选重复query与固定余量估算token，取价格向上整为microUSD；请求前条件UPDATE原子预留并登记调用，失败/超时保留费用预留。供应商usage可用时只结算不超估算的余额，超额告警并停模型；未知计费不退还。每身份每分钟最多20新批次、2次模型重排、60个事件请求；最多20事件/请求；全局月限含索引和排序。模型等待1.2秒，超时回退并记timeout；调用可能仍在供应商执行，预留不退款，后台不发第二模型。

作品理解复用既有AI生成的元信息；index时补入既有HTML可见文本提取，不覆盖作者内容、不为每次浏览生成概要。图片/截图理解不属于所有作品必需前提；无法获得源码使用已知元信息并记录来源。离线BGE索引与在线兴趣向量由同版本作品向量加权获得，无外部向量数据库。

### 实测冻结的主路径与复审

`docs/logs/2026-10-03-explore-recommendation/model-benchmark.json` 保存同一546件当前公开目录、30中英文描述标注场景、每场景20个固定候选的比较。BGE-M3向量基准 hit@3=1.00、MRR≈0.961；BGE reranker hit@3≈0.933、MRR≈0.923，本地网络下median≈1.39s、p95≈2.73s。标注仅证明描述相关性，向量基准使用离线查询向量，产品兴趣使用所看作品的加权向量；不能据此宣称线上增长或绝对模型最优。

选择：BGE-M3离线索引 + 会话/近期作品向量匹配 + 质量信号/多样性/探索，为活动 `content` 算法。没有证据支持专用重排额外费用/等待，故主路径不发在线模型请求。`bge` 是当前已实测且可由局部运维切换的对照算法，维持相同输入/输出合同、1.2秒超时和预算保护，前端与事件无需改变。Jev返回402，OpenAI没有凭据，现有DashScope直连及实际部署的兼容网关均返回invalid_api_key，不声称三者质量差；这些可选依赖不进入主链路。

新增生成概要不必另调用不工作的生成服务：已有AI元信息与可提取的HTML可见文本作为索引证据。新增AI正常费用仅作品索引/更新，保守预算按输入UTF-8上界保留，Cloudflare embeddings响应无usage时不假称精确账单。只在受控重排实验产生在线模型费用；模型总月限继续$10。实现前复审确认该选择保持用户的低成本、预算内最好、完整局部实验目标，没有删除任何R1–R10结果；排序边界和回退均保留。design-review: passed（当前细化与活动算法范围）。

### 实验分析冻结

主要指标为有真实曝光的访客中打开作品的比例，按访客汇总，回退仍归原实验组；手动模式另列。至少运行7天、两组各300名曝光访客，按完整周窗口复核一次。相对提升≥10%、打开率差的95%区间下界>0，且无护栏恶化，才有资格评审扩大流内比例，不自动推广到其它入口。两组各50次打开后，加载错误或负反馈比例恶化超过2个百分点则建议暂停。样本不足时继续局部实验或停止，不能宣称有效。report包含原始聚合计数、指标、区间、算法/回退和已知usage费用/保守预留；iframe load/error只是浏览器信号，跨域HTTP错误页未必触发onError，不据此证明作品可玩或学习完成。DNT与关闭保存的会话不进入持久实验统计。当前以原目录为内容基线，不引入训练点击模型。
