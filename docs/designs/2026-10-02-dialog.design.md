# 统一 Dialog 与名字设置弹窗

## 当前目标与用户链路

2026-10-02 用户 review 名字设置后要求用弹窗替代平铺表单，并要求核查既有规范、参考 shadcn 封装可复用组件。本变更取代 profile-name-reminder 设计中的卡片布局与“无自动弹窗”决策，其身份、唯一性、持久化和会话隔离合同继续有效。flow=standard / L2，retrospective_state=pending；design-document required，plan not-required，单批闭环。

未设置公开昵称及用户名的用户登录或刷新正常主界面 → 会话恢复完成、其它全局弹窗关闭后，居中显示名字设置表单并聚焦昵称 → 输入昵称和可选唯一用户名 → 保存成功、弹窗关闭 → 我的主页和公开作品使用既有保存结果。失败保持弹窗和输入，就地提示可重试。

用户点击“稍后再说”、右上关闭、Esc 或遮罩 → 关闭，本次应用访问按 user ID 不再自动提醒，路由切换保持安静 → 仍可从“我的主页”编辑资料 → 刷新/重新进入再提醒。保存期间所有关闭方式和重复提交均禁用。有名字、未登录、会话加载中、SDK/CLI 授权独立页面不自动弹出；账号切换清草稿。

## 现状、候选与主链路

登录 AuthModal 和确认 ConfirmDialog 各自实现 div 遮罩和固定布局，缺统一焦点隔离和 Dialog 语义；shared Popover 是非模态组件，无法直接承接模态焦点与背景隔离。项目未发现统一 Dialog 规范、shadcn 配置或已有 Dialog 依赖。

- 复用当前 div 骨架：重复已有焦点、语义和关闭缺口，不能提供可靠统一规范。
- 原生 dialog：可提供原生焦点与隔离，但受控 open、portal、关闭拦截和跨弹窗样式需自行定义，后续消费者与参考组件行为有差异。
- 采用 shadcn/Radix 的组合模型：选择本方案，新增单一 @radix-ui/react-dialog 依赖，复用其 portal、focus trap、背景隐藏、滚动锁、Esc/outside 生命周期；项目只负责品牌样式、本地化关闭标签和业务关闭策略。参考 https://ui.shadcn.com/docs/components/radix/dialog 与 https://www.radix-ui.com/primitives/docs/components/dialog 。不运行 shadcn 全站初始化，不改 Tailwind/theme。

## 组件规范与 owner

共享组件位于现有 frontend/src/components/dialog.tsx：Dialog（受控 Root）、DialogContent（Portal/Overlay/Content/关闭按钮）、DialogHeader/Title/Description/Footer。三个当前消费者：名字引导、登录、确认，删除其重复遮罩及标题/关闭骨架。宽度由 sm/md 两种已存在需求决定，手机左右留白 16px、最大高度适配动态视口并内部滚动；统一白/深色面板、圆角、边框、紫色 focus ring、z-index 100。所有弹窗必须提供可访问标题及关闭标签；无可见描述的登录弹窗显式不关联 description。

Dialog 只持有模态交互原语，不知道用户、请求和 store；业务 open/关闭/保存归现有 manager/store。程序化打开没有 Radix Trigger，组件通过 autofocus 生命周期记录并恢复原焦点；昵称使用 Radix 的首次聚焦，不另加原生 autoFocus。关闭按钮、Esc、outside 在 dismissible=false 时均不可关闭；业务 onOpenChange 同样守卫保存中。确认弹窗所有取消路径 resolve(false)，确定 resolve(true)。登录业务及提交行为保留；名字自动显示通过组件同步当前会话与既有 beginNameSetup，draft/store 仍唯一拥有编辑状态。其它全局 Auth/Confirm 打开时名字弹窗暂时不挂载，不叠加两个自动模态；草稿保留，前者关闭再显示。成功关闭不记录跳过。

抽象审计：保留实际三个消费者共享的布局、焦点和关闭生命周期；删除三个遮罩/标题/关闭平行实现；不新增全局 modal service、队列、schema、主题库或业务表单框架。不触达其它非本任务 overlay。
