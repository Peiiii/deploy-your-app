# 发布页布局精简

## 目标与现状

用户希望当前 `/deploy` 更优雅、清晰，保留此前新增的内容来源语义和整体品牌风格；不追求极致简约，项目名称必须常显。原界面中来源、工具按钮均用独立胶囊形状，HTML 提示与标题重复，长使用提示占据默认流程。属于 small-change、standard；最终范围为局部视觉与文案 L1，不改变部署合同或字段可用性。

## 方案

来源控件比较保留分散按钮、来源说明卡片、紧凑分段控件三种形式。说明卡片会增加装饰和阅读量；保留分散按钮无法收敛层级。采用有名称的三列分段控件，选中态有紫色底与文字，发布按钮使用实色主色。仍保留来源名称和一句对应操作说明。

- 用户允许适度改变整体结构，但实际对比后明确反馈开放画布不如卡片聚焦，要求注意力分层。最终采用 `max-w-3xl` 的白色/深色主卡片，以细边框和轻阴影突出内容；卡片中的输入区使用轻微底色区分层次。标题与结果说明在卡片上方居中，侧栏与页头保持一致。不增加引导步骤、装饰或配置。
- HTML 输入区与导入/示例工具合成一个编辑面板，屏幕阅读器保留内容标签，默认减少重复标题与独立彩色按钮。
- ZIP/GitHub 使用紧凑呈现，保留文件限制、公开仓库要求及输入错误；共用的 HTML/ZIP 表单以 `compact` 参数选择呈现，项目设置保持原布局；GitHub 表单只有发布页调用，直接精简。
- 按用户最终要求，项目名称标签和输入框始终可见；“可选”只表示不必填写，不作为隐藏信息的依据。仍编辑原 store 字段，名称自动提取逻辑不变。
- 使用规范复用已有 compact 形态，放在发布按钮下方；保留可访问链接。部署进度、失败、成功和再次发布仍由原入口负责。

## Owner 与边界

保留 `NewDeployment -> presenter.deployment -> deployment.store`。不增加状态、副本、抽象组件或新后端入口。HTML/ZIP/GitHub 上传、输入、清空与 busy 禁用保持原合同。不修改侧栏、全站导航、部署引擎或线上配置。

用户补充整体风格约束：产品同时包含浏览/刷内容属性，并非追求极致简约的沉浸式工作台。对照首页 `HomeDeploySection`、设置页 `DeploymentSourceTabs` 和实际侧栏，沿用现有 brand 紫色、slate 灰白/深色表面、全站字体与 rounded-lg/xl 圆角。选中来源使用浅紫底和品牌色文字，和侧栏选中态呼应；不引入另一套配色或字体，也不靠隐藏项目名称减少默认信息。

## 验收与交付

1. 在运行本次源码的 `http://localhost:5194/deploy` 选择三种来源：名称、说明、表单和 URL 一致；空输入不能发布，输入 HTML 或有效仓库地址后可继续原登录流程。
2. HTML 可粘贴、导入文件、插入示例；名称输入始终可见，来源往返保留既有 store 行为。ZIP 选择/清空及 GitHub 无效输入提示保持可用。
3. 中英文、浅深主题、390px 与桌面尺寸真实渲染：无水平溢出，控件有键盘焦点，来源仍可理解，默认 HTML 视图能更早看到发布动作。

定向 lint、frontend tsc、前端 build；真实浏览器核对上述相关交互，不创建镜像实现的测试，不触发真实外部发布。交付本地预览、效果截图和提交/同步状态，优雅程度由用户确认。design-document=required；plan=not-required，单批闭环。
