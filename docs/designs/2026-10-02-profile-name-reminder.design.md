# 公开名字设置引导

## 目标与范围

用户要求改善“创作者 XXXXXX”的默认展示，不强制设置，但每次进入时提醒未设置用户；参考抖音/小红书的账号资料体验。2026-10-02 用户确认继续采用昵称允许重名、账号用户名唯一的方案。flow=standard，风险 L2，retrospective_state=pending。设计文档 required；单批可闭环，plan not-required。

现有 owner：AuthStore 保存当前用户，AuthManager.updateHandle 调用 PATCH /me/handle，MyProfileManager 管理个人资料，public-author package 决定公开名称（昵称 → @用户名 → 匿名编码）。API 已检查用户名冲突且数据库有唯一约束；昵称不要求唯一。保留既有协议与持久化，不新建账号标识。

## 用户链路与交互

未设置有效公开昵称和用户名的登录用户进入正常主界面，在 Header 下看到“给自己起个名字，让大家认出你的作品”的轻提醒。点击“设置名字”，卡片原地展开表单：公开昵称为主要输入，账号用户名可选，说明用于唯一主页地址。昵称支持现有字符范围，最多 50 字符，不包含邮箱和控制字符；用户名沿用 3–24 位字母、数字和短横线，忽略大小写并转为小写。输入昵称是这条引导链路的完成条件；已有用户名的账号不重复提醒。

保存期间禁止重复操作，保留当前页面；失败就地展示中文/英文错误且保留输入，重名可修改再保存。成功由同一 AuthStore 更新用户，卡片立即消失；公开作品与主页按现有公开名称规则使用新昵称，已加载的作者信息在后续查询时刷新。用户也可通过原个人资料页继续修改资料。

“稍后再说”关闭整个提示，在当前应用访问期间按用户 ID 记住，路由切换不重现；刷新/重新进入应用重现。退出登录或切换账号不能泄露另一个账号的表单草稿；异步保存不能在会话切换后覆盖新账号。未登录和会话恢复中不显示；SDK/CLI 授权独立页面不加载提示。桌面和手机都可操作，无自动弹窗，无强制注册步骤。

候选：每次弹窗会打断发布；跳转完整个人资料页使用户需要理解与当前目标无关的简介、链接、置顶应用。选择全局轻提醒与原地填写，复用现有更新能力，仅增加本功能草稿和提示状态。

## 验收与交付

1. 本地完整产品与真实本地 Worker/D1：正常注册/登录无名字账号 → 提示 → 展开 → 填昵称与可选用户名 → 保存 → 提示消失 → 刷新、个人资料/公开主页显示保存名字。
2. 未设置账号关闭提示 → 切换页面仍隐藏 → 刷新再次出现；未登录/已有名字账号不出现。手机无横向溢出，键盘可操作。
3. 两个本地账号使用相同昵称可保存；第二个账号使用相同用户名看到本地化冲突提示，换名后可保存；服务错误保留草稿。覆盖保存期间会话切换的隔离。

证据：frontend tsc、触达文件 lint、定向 manager/store 边界验证和真实浏览器本地链路（开发证据与真实依赖证据区分）、frontend build；diff-only 实现 Review。没有维护性检查入口时手工 diff Review。按项目授权精确提交并普通推送 origin/master；通过既有 pnpm deploy:pages 发布前端，核对 gemigo.io 产物资源一致后提供用户入口。生产不修改用户账号资料。
