# 免费应用数量与存储回收

## 来源与范围

2026-10-04 用户确认：免费账号最多保留 200 个应用，删除旧应用可恢复名额；不设置账号总存储额度。超过 200 个属于付费扩容。此前每天新增 20 个的规则由总数规则替换。保留单应用现有体积与文件数限制。当前不存在平台套餐、价格、支付和付费权益，因此本次落实免费额度与明确的扩容提示，不虚构购买成功或付费账号。付费接入方式待用户回复。

本任务为 standard / feature，涉及数据库并发、跨运行时文件删除和生产交付，风险 L4。使用现有 projectRepository、项目 Durable Object 和 Node 发布队列，避免新建配额/存储框架。

用户后续明确：免费上限放宽至200；管理后台经营总览显示当前应用数量前十的用户，支持查看该用户应用。原100提案被此决定替代。

## 用户链路

1. 免费创作者从发布入口创建第 200 个应用，成功；第 101 个明确提示免费额度、删除旧应用或付费扩容。草稿、私有、离线应用均计数，日期不影响额度。已超过额度的已有账号保留访问和更新能力。
2. 创作者删除旧应用：串行关闭该项目的写操作，Node 等已接受作业结束后删除该应用 R2 文件和临时源；完成后删除数据库记录，名额及地址可复用。存储暂不可用时保留记录和地址，后台重试，避免释放地址后误删新应用。
3. 创作者反复更新应用：当前和上一版保留；下次成功发布扫描全部历史版本，回收此前失败的清理与残留旧 current；失败发布保留线上版本。

## 设计

- 总数唯一 owner 为项目仓库。前置检查避免无效分析，INSERT SELECT 的同一条 SQL 再检查未删除项目总数，防并发绕过。恢复和更新不新增用户配额规则。免费上限常量为 200，无日历重置。
- API 返回 `PROJECT_COUNT_LIMIT`、limit=200、upgradeRequired=true；浏览器使用中英文提示，CLI/API 获得可读错误。不新增不存在的付费 checkout。
- 现有 AppGateway 按项目串行处理发布、上传源、封面、修改和删除；用户请求不能通过自行添加 HTTP header 绕过串行入口。Gateway API 连接生命周期沿用已有停止机制。
- Node 发布队列也处理存储删除。持久化项目 UUID 删除收据，在收到删除意图时拒绝该旧项目后续发布；删除收据完成后重复请求只返回完成，绝不再次删除已复用地址。Node 重启后重试恢复。R2 批量删除检查单键错误并分页；发布历史回收使用当前/上一版指针，不删除新版本。
- D1 `storage_deletion_pending` 保存需重试的项目。正常成功删除后清掉整行；失败保持地址占用及未完成名额，两分钟 cron 重试，清理后释放。Node/Worker 部署先后保证删除 endpoint 先可用。
- 临时 ZIP 的既有一天回收补齐分页；不缩短有效期。管理员后台截图任务在删除请求时失效，不修改 SDK 用户业务数据。
