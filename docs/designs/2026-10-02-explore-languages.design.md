# Explore language matching

## Goal and sources
User asks to implement the discussed language solution, with the expected language selected on first visit and a prominent, easy-to-find switch on desktop and mobile. Project managed delivery authorization includes commit, push and online acceptance. Flow standard; risk L3 (persistent app language and cross-runtime detection); design-document required; plan not-required (one cohesive delivery).

## User journeys
1. First visit /explore: browser's first valid language seeds application-language preference before the first request. The compact content-language button beside search shows the selection; its popover explains the automatic origin. Matching apps appear; their cards identify actual app language. A Chinese/Thai browser receives Chinese/Thai apps respectively even when platform UI falls back to English. Existing explicit app preference wins on later visits.
2. Open the content-language button, then click 中文 / English / ไทย or another available language: immediately start page one for the new selection, preserving category/search. Multiple selected languages are supported; 全部语言 shows the whole catalog. Refresh preserves explicit choice, including all. A visible automatic option restores browser default. Empty matched results show an explanation plus a direct all-languages action; errors show retry. No silent foreign-language filling.
3. Author opens project → display settings → app language: sees detected / unconfirmed status, selects supported languages, saves through the existing owner-authenticated project PATCH. This declaration remains authoritative across redeploys. Unconfirmed clears declaration and schedules re-detection.
4. Public Live app after successful publication: the existing scheduled Worker scans bounded candidates, including legacy applications. Screenshot service renders the deployed page and returns bounded body / UI-control text through authenticated service binding; existing AI service classifies interface language. A version-guarded repository write cannot override author declarations or newer releases. Insufficient evidence is explicitly unknown, not English; rendering/classifier failures stay pending and retry without stamping a revision. Scanning never delays publication.

## Decisions and owners
- Keep UI-language i18n separate from app languages and metadata localization. Never infer supported languages from listing translations, source filenames, repo country, or README.
- Default language-matched feed plus explicit all is chosen over global mixing or isolated national sites. Unknown apps remain accessible in all and a direct unconfirmed filter. Author-confirmed language-independent apps use zxx and are eligible in every language.
- One `app_language` JSON column owns languages, source (detected/author), release revision, checked time. Author input is validated BCP47 primary language codes; empty means unconfirmed. Auto detection returns only one high-confidence interface language; metadata translations and a multilingual directory are not proof of UI support. Author can declare multiple.
- ProjectRepository owns atomic persistence; ProjectLanguageService owns scan policy, bounded extraction and stale guards; AIService owns model transport; screenshot Worker owns browser lifecycle. Existing deployment reconciliation cron calls a bounded batch, not a public-read mutation. Successful classifications repeat only on new successful releases / manual reset; unavailable services retry through the scheduled owner, never on browsing.
- The newer master performance owner queryExplorePage filters in D1 before ranking/count/pagination, returning only one page plus small language facets in one batch; no full-catalog transfer. Shared Popover is reused for dismissal/focus rather than duplicating menu lifecycle. Public API without language query keeps existing all-language behavior for other consumers. Frontend ExploreManager transports preferences, guards requests against filter changes, and clears stale rows before language refresh. Shared preference store is only browser app-language owner and tolerates unavailable localStorage.
- A compact content-language button beside search opens endonym multi-selection; no permanent expanded panel. Header's existing language entry becomes visible on mobile and contains labeled UI language plus the same app controls. No new global settings system. Existing theme/profile settings stay at their existing owners.
- Unknown/low confidence exclude from matched feed but remain in all/unknown. API supplies available languages and counts for transparent choice. Short neutral apps are unknown unless author confirms language independence.
- Homepage discovery shares the same preference and visible control (otherwise it would contradict Explore). Extension API stays all unless requested. Admin-owned per-project detect endpoint (admin session or scoped content-service token only for this action) is the current operational consumer for immediate bounded legacy backfill; it calls the same scanner and respects manual/private/version guards. No full app translation, education taxonomy, login-page traversal, whole-site multilingual audit or automated navigation clicks. Educational app detector prioritizes UI controls over foreign-language exercise text.

## Runtime/security and lifecycle
Content endpoint authenticates a new shared secret, only accepts HTTPS *.gemigo.app URLs with no credentials/custom port, validates redirects/final host, bounds extracted text and browser time, and closes browser in finally. No app cookies/account sessions. Detected public text only enters existing AI transport. New binding/token do not replace existing production secrets.
Scan batch is bounded and sequential (three apps per 2-minute cron); model request 12s, browser navigation 12s. Version guard compares successful release revision and live/public/nondeleted state; author declaration wins. Valid insufficient-evidence results recorded once per release; service failures remain pending/retryable. Existing app language applies until an updated scan succeeds, then becomes known/unknown as evidence warrants.

## Design review
Passed before implementation: independently checked original user defaults and discoverability against journeys; unknown-only catalogs cannot silently show wrong languages; endpoint is authenticated and restricted to public deployed app domain; version/manual guard protects race boundaries. No open findings. Integration re-review 2026-10-02: preserve new master D1 pagination and Popover owners; three SQL statements plus current-page author lookup (constant query count), language filter is parameter-bound. Reviewed additive homepage shared-consumer coverage and authenticated per-project admin backfill before implementation; both use existing owners rather than a parallel detector. New names pay rent: one service separates scan lifecycle from deployment status, one column avoids duplicating localized listing metadata, shared controls serve both discoverability entry points. Deferred global settings redesign has no current requirement beyond accessible language settings. Contract review: all required paths include real Explore/project entry points and production backfill, rather than a cosmetic selector alone.

Failure-semantics re-review: production service failures must not masquerade as a classified unknown; scoped scan reports distinguish render/classifier failures and bounded backfill halts on systemic outages. Added regression for no write/retry eligibility.

User-directed refinement: keep only the selected content-language button beside search, desktop and mobile; expanded multi-select/reset/help appears on demand. Homepage uses the same compact entry. Website display language remains in the visible header menu. This supersedes the always-expanded discovery panel; controls remain reachable in one click. Re-review passed against EL02 discoverability/space/keyboard/outside-close/mobile constraints.

Production browser compatibility: the installed Puppeteer 1.0.x transport consumes ArrayBuffer frames; runtime >= 2026-03-17 otherwise supplies Blob, hanging connect. Screenshot worker compatibility config explicitly retains ArrayBuffer semantics (upstream issue cloudflare/puppeteer#193). Remove this flag when migrating to a library supporting the new frame type.
