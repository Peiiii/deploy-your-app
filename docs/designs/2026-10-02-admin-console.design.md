# GemiGo 后台管理网站

## 来源、现状与决策

2026-10-02 用户要求「专门的管理网站」「至少提供管理和大盘」「独立的账号系统」「初始的用户名和密码」「支持改密码」，并明确先设计、自审到满意再落地。现有 `admin/` 与 `workers/admin/` 已服务 admin.gemigo.io，独立 admin cookie、初始 Secret 和本机私有凭据已存在；目前只有事件分析与采集设置，网页缺密码管理与业务管理。用户继续明确这是后台管理网站。

采用 standard，风险 L4；复用已有站点、Worker、业务 D1 和分析接口。替代方案是在主站加入管理角色，或重新创建第二后台，前者违反独立账号预期，后者制造重复部署与认证 owner。初始管理员沿用 admin，保留现有私有凭据；不在 Git 或页面预填密码。AI 依已有全托管授权完成部署。设计与实施同一单阶段交付，plan not-required（可单批闭环）。

## 使用链路与界面

管理员打开 https://admin.gemigo.io，以独立账号登录，自动加载经营总览：累计注册用户、有效应用、近 7/30 日部署与成功率、真人应用访问、每日趋势、来源与失败原因；数据以业务表事实为准，UTC 日期和统计范围可见。切换用户管理后按姓名/邮箱/handle 搜索并分页，查看创建时间、应用数和有效会话，确认后撤销指定用户主站会话，看到结果与操作记录。应用管理按名称/slug/所属用户搜索、状态筛选，查看所有者、部署状态、公开性与最近时间；确认后切换公开展示，再刷新看到持久化结果。公开性只控制平台展示，应用链接的访问控制仍遵循现有产品语义。部署记录可按状态与名称查询，显示来源、渠道、开始/结束、耗时及错误代码。

左侧导航运营管理（经营总览、用户管理、应用管理、部署记录）、产品分析（复用已有概览、功能、漏斗、明细）、系统（采集预算、账号安全、操作记录）。页面有真实加载、失败重试、空结果、分页和明确操作反馈。手机侧栏变为横向导航，列表在卡片内部滚动。认证恢复自动加载默认大盘，不要求额外点击。

账号安全：当前密码、新密码、确认新密码；8–256 字符、禁止与当前相同、匹配确认。提交中禁用；错误保留表单，成功清除密码并退出，提示重新登录。旧密码与所有旧会话失效。退出清空管理数据。默认单管理员与既有 username 配置一致，无当前消费者的多管理员/RBAC 不进入实现；后台不会自行创建或删除真实业务资源。

## owner、持久化与安全边界

`auth.ts` 唯一负责密码哈希、账号读取、会话与改密。新增 admin_account 单行（password_hash、version、updated_at）作为持久密码权威；首次登录通过 INSERT OR IGNORE 从既有 Secret 初始化，无并行可登录密码。会话 token 哈希绑定账号版本（版本 0 保持旧 token 哈希算法以兼容当前会话），认证按当前账号版本推导查询哈希。无需改变旧 session 表结构，迁移不会破坏旧 Worker 登录。登录使用验证时版本创建会话，防止旧密码验证与改密竞态留下有效会话。改密采用版本/哈希 CAS 更新，D1 batch 同事务撤销全部管理会话并记录无密码的审计事件；并发只有一次成功。运维重置脚本更新同一账号 owner、提高版本并撤销会话，通过权限 0600 临时文件传哈希，避免哈希出现在命令参数。

所有 /api 数据在认证后返回 private no-store，写入要求同源 Origin，限速先于密码推导且不随网页改密重置额度；保留 PBKDF2 100000 与 Web Crypto 合同。敏感校验输入有上限，错误 JSON/字段返回 400；基础设施错误返回 500。D1 batch 事务依据 Cloudflare 官方 D1 API 文档。管理业务查询在 Worker 的 operations.ts 集中，显式字段白名单，不读取用户 password_hash/OAuth 凭据/源码。应用可见性使用期望旧值 CAS，冲突返回 409；修改与审计同一 batch，未知资源无成功日志。撤销会话不删除账号或应用。审计只保存管理员、动作、资源 ID、时间及必要摘要。

抽象审计：保留已有 React shell、分析组件、fetch 与认证；新管理页面共用 api 与表格分页 UI，按直接业务职责拆分，不创建通用 CRUD 框架或第二状态系统。业务原表仍为事实 owner；admin_account 为独立管理凭据 owner，初始 Secret 仅为空表初始化。运维重置与网页改密收敛到同一表与版本语义。

## 验收与 Review

用户黄金路径：打开线上入口 → 初始账号登录 → 总览看真实数据 → 用户搜索 → 应用搜索及公开性修改 → 部署失败筛选 → 账号安全验证当前密码并修改 → 自动退出 → 旧密码失败、新密码成功 → 刷新仍可登录。AI 先以隔离 D1/组装 HTTP 边界验证全部写入、错误、CAS、竞态与会话失效；线上以真实私有凭据验证登录与数据，对隔离验收资源验证管理操作，验证改密后恢复同一凭据便于用户使用。复用旧分析和预算并验收桌面/手机真实渲染。

设计 Review：从用户原始要求反查覆盖完整；补入认证恢复自动加载、运维重置同步、登录/改密并发版本控制、可见性非访问封禁提示、真实表白名单、事务审计。当前无未关闭 finding，design-review passed。审美由 AI 检查层次、可读性、留白、表格与移动端；用户可继续判断偏好，非人为新增审批门。
