# 统一轻量 Popover

用户要求：首页「更多方式」展开后点击其它位置自动关闭，并提供统一组件。线上修前复现：展开后点击发布区标题，`details[open]` 仍存在。任务按 standard / L2 交互实现，发布按 L4 核对产物。

用户链路：首页点击「更多方式」看到 GitHub / AI 发布内容，点击浮层内的文字或复制按钮保持展开；点击外部标题关闭，点击 HTML / ZIP 同时关闭并进入对应发布表单。键盘 Enter / Space 展开、Tab 进入内容，Esc 关闭并回到触发按钮，Tab 离开组件关闭。手机浮层完整留在视口内。

## 设计与边界

- 新建 `frontend/src/components/popover.tsx`，与共享控件同目录。组件唯一拥有临时展开状态、触发按钮、外部 pointerdown / focusout 的关闭、Esc 和事件解绑；调用者提供触发内容、样式和浮层内容。通过 children 的 close 回调表达选择后关闭，没有全局 store、portal、菜单 DSL 或新依赖。
- 首页替换原生 details；GitHub 选择后先关闭再执行已有发布入口，AI 复制保持打开以显示反馈。沿用当前手机相对整个操作区、桌面相对触发按钮的定位，保留内容和样式。
- 语言切换是已有第二消费者：删除独立展开状态和覆盖整页的透明遮罩，使用同一 Popover；语言选中后关闭。外部点击不被遮罩吞掉，原目标动作同次点击执行。
- 参考已有账户菜单的外部点击 / blur / Esc 实现，但该文件已有其它任务未提交修改，本任务不触达。共享组件当前两个消费者，抽象保护相同临时交互生命周期，避免抽象高于证据。
- 不改变发布业务、账户菜单、导航、语言选项和数据持久化。没有 planned-path 或 diff-only maintainability 脚本，按当前共享组件目录及 findings-first 审查。

design-document: required；plan: not-required（单批闭环）。方案 Review：从用户要求独立核对外部点击、内部动作、键盘焦点、触发开关、移动端定位及两个消费者；无需新库或多层 API，未发现阻塞 finding；design-review: passed。
