# GemiGo 实时 AI 语音接入方案

日期：2026-10-03。状态：早期语音专题方案，尚未实现或发布；平台统一 Key 的推荐策略已由用户后续提出的应用自带 Secrets 方案取代。当前上位方案见 [应用级 Secrets 与 API 中转](2026-10-03-app-secrets-api-gateway.design.md)，本文保留音频链路、宿主候选和验收事实供复用。此次交付止于方案，不启动产品开发。

## 用户结果

用户在 GemiGo 打开“小伴”，点击开始通话，首次完成登录与麦克风授权后，用中文或英语连续交流，能实际听到 AI 回答；可以打断、静音、挂断，再次开始通话。声音被浏览器暂停时，能点击恢复；无权限、断网或额度不足时，看到可操作的提示。

首版建议使用平台登录身份、仅对小伴启用、平台提供有额度上限的试用。匿名消费、创作者自行填 Key、付费套餐均是后续可选决策，不自动承诺。当前“小伴”本地通话无需平台登录，接入后新增登录前提必须在界面说明。

## 已核实的事实

- `server/src/modules/deployment/deployment.service.ts` 将构建输出交给 Pages、R2 或本地静态目录。用户的 `npm start` 不会成为持续运行的线上应用服务。
- `server/src/index.ts` 是平台部署引擎；`scripts/deploy.sh` 管理其阿里云 Docker 容器，并挂载构建数据与 Docker socket。语音进程应独立部署，避免依赖构建引擎的权限与发布生命周期。
- `workers/openai-gateway-worker/src/index.ts` 只登记文字聊天与模型列表；其处理器使用服务端 Key，但当前没有应用鉴权与用量控制。不能直接把这个接口当成已完成的语音授权方案。
- `workers/api/src/services/sdk-auth.service.ts` 与其 repository 已有应用身份、用户身份、Bearer Token 校验，可复用。现有 scope 授予接受额外字符串；新增 `voice:use` 本身不代表应用已获平台付费资源许可，还必须检查真实项目与启用策略。
- `workers/api/src/services/sdk-cloud.service.ts` 的云函数入口目前仅实现 `cloud.ping`，不能部署用户自定义的 Node 后端。
- 网页首页预览与探索流的 iframe 当前源码已加入 `allow="camera; microphone"`，见现有 `2026-10-03-preview-media-permissions.design.md`；本轮没有重新证明它已在线上生效。接入验收复用该 owner，不重复修改权限机制。
- `/Users/peiwang/Projects/voice-companion/server/realtime.mjs` 已跑通 Qwen 双向音频、转写、服务端 VAD 和打断；前端已经分离麦克风与播放 AudioContext，并提供试听与恢复声音。
- 小伴仍硬编码本机 `ws://`、`/api/status`、`/api/chat`，后端只允许 localhost。静态上传无法自动补齐这些接口。
- 目前物理声音证据仅包含用户确认系统播放器样本可听见；应用内实际通话可听见仍需完成用户验收。不能用收到音频、波形有能量或浏览器播放图标替代。

## 选型

| 候选 | 完整性与代价 | 结论 |
| --- | --- | --- |
| GemiGo 页面 + 平台管理的独立 Node 语音服务 | 复用现有 `ws` 和已验证的 Qwen 协议；新增独立容器、域名及平台授权；可在现有阿里云基础设施承载，需先核实主机资源和网络 | 推荐首版 |
| GemiGo 页面 + Cloudflare 实时语音 Worker | 官方支持入站、出站 WebSocket，但要迁移连接生命周期、限额协调及关闭逻辑，并实测到北京 DashScope 的链路 | 可行备选；海外使用或现有主机不合适时重新比较 |
| 任意 Node 应用一键托管 | 还需用户运行时隔离、Secrets 管理、进程调度、路由、日志、健康检查与计费；工作量超出首个语音消费者所需 | 单独立项，不作为本次前置条件 |

推荐 Node 的依据是现有可用实现与阿里云部署基础；国内延迟优势仍是待测假设，不作保证。实施前先从候选宿主跑一次真实 Qwen 往返，并检查并发通话与构建时的资源影响。宿主失败则调整部署位置，保持平台接口合同。

官方协议依据：

- [Qwen WebSocket 连接协议](https://www.alibabacloud.com/help/en/model-studio/realtime-websocket-overview)：服务端握手携带 Authorization，按地域选择接口。
- [Cloudflare WebSocket API](https://developers.cloudflare.com/workers/examples/websockets/)：Worker 可以接受客户端连接并连接上游 WebSocket；这证明备选技术可行，不证明当前 GemiGo 已具备语音服务。

## 推荐主链路与职责

```text
小伴网页（GemiGo 静态托管）
  ├─ HTTPS → GemiGo API：身份校验、申请会话、预留额度
  └─ WSS   → 独立语音服务 → DashScope Qwen 实时语音
                         └─ 内部 API → 会话状态、用量与释放预留
```

1. 小伴通过现有平台登录得到应用 Token；用 HTTPS 申请语音会话。API 校验 Token、真实 appId、用户、应用启用状态、允许的来源、模型与剩余额度。
2. API 原子预留可用额度，生成短期单次连接票据，返回语音地址及本次时长上限。建议票据有效期 60 秒；不把平台长期 Token 放到 WebSocket URL。
3. Node 服务验证签名、来源和有效期，并通过内部接口原子消费票据。验票失败不连接 DashScope；有效票据只能建立一次通话。
4. Node 使用服务端 Secret 连接固定 DashScope 上游，完成 session 配置后通知应用“已连接”。允许的角色、音色、模型与时长由平台策略控制，不接受浏览器指定任意上游地址或 Key。
5. 前端上送音频、播放下行音频，保持现有转写、打断和试听功能。连接等待、音频恢复、静音状态和失败原因分别呈现，避免只显示“已连接”却掩盖播放暂停。
6. 挂断、超时、上游关闭、队列超限或服务下线都由连接 owner 关闭双向连接、停止计时并上报结束。前端同步停止播放、释放麦克风。断网后用户重新开始，新会话不承诺继承前次上下文。

权威边界：API Worker/D1 拥有身份、应用许可、额度预留与会话记录；Node 拥有活动连接和上游协议生命周期；小伴拥有录音、播放和交互状态。实时音频只经过语音服务，不经构建任务或 D1。

用量控制与实际计费分开：上线前设置单次时长、用户并发、应用总并发、用户日额度和平台总预算。预留必须原子执行；异常退出保守占用预留，按明确的期限和对账规则收敛。采集供应商 usage 时在 UI 事件过滤之前处理，取消的回答也可能已消耗资源。分钟数用于限额，账单估算依据上游用量与届时价格，不把通话分钟直接当成实际费用。

## 具体改动与实施顺序

### 1. 宿主和协议预验

从现有阿里云宿主验证 DashScope 鉴权、模型权限、一次完整语音回答及连接清理；核对域名/TLS、主机资源、部署隔离和日志。模型沿用已跑通的配置，升级另做验证。记录开始连接、上游就绪、说话结束、首段可播放音频时间；不先承诺未实测的延迟或容量。

### 2. 平台会话与额度

拟新增 `workers/api/src/controllers/realtime.controller.ts`、`services/realtime.service.ts`、`repositories/realtime.repository.ts` 及适用 D1 migration；修改 `routes.ts` 与 `types/env.ts`。复用现有 SDK Token 校验，不另建用户系统。

拟议接口：`POST /api/v1/realtime/sessions` 创建会话；内部鉴权接口消费票据、报告存活与结束。D1 保存会话 ID、appId、appUserId、来源、创建/过期/开始/结束时间、状态、预留量与已知上游用量。签名和内部认证使用专项 Secret，不复用部署引擎访问 Token。

应用启用采用首版服务端项目白名单和明确额度配置；首个消费者不必先建设完整的作者控制台。签发接口检查项目实际存在且可用，scope 不能替代许可。公开试用前必须完成额度控制。

### 3. 独立语音服务

拟在本仓库 `services/realtime/` 建立独立 Node package、Dockerfile 与部署入口。迁移小伴的 Qwen 协议 owner，补票据校验、心跳、超时、时长上限、双向背压与结束对账。独立容器不挂载 Docker socket 或用户构建目录，Secret 不进入静态包。

先单实例并设置明确并发上限；实例故障由预留期限回收，恢复后允许新通话。发布先停止接受新会话，等待有上限的已有通话结束，再切换健康实例；不套用构建任务的 drain 完成条件。多实例扩容另按实测需求设计，当前不能把内存计数宣称为全平台限制。

### 4. 小伴接入和发布包

修改 `/Users/peiwang/Projects/voice-companion/public/app.js` 与构建配置：加入平台登录、会话申请、可配置 API 地址和 `wss://` 连接；服务器能力检查改走平台状态响应。静态 `dist` 上传 GemiGo，Node 语音桥转移到平台服务后不再作为网页包内可执行后端。

当前 DeepSeek 文字模式也要明确迁移：首版保留既有 DeepSeek provider，由受同一身份和额度策略保护的文字入口承接，或接入改造后的平台文字网关；不能静态上传后留下失效的 `/api/chat`。将文字入口和成本管理补入同批交付，避免语音可用而原功能丢失。浏览器音频权限按现有预览修复方案验收。

### 5. 真实使用验收与小范围启用

先仅启用小伴，走下述矩阵；通过后再考虑第二个应用和稳定 SDK。复用音频会话生命周期而不提前建设多供应商注册表、通用后端运行时或自动改写任意项目代码。

## 验收标准

| 场景 | 成败判定 |
| --- | --- |
| GemiGo 独立页面首次通话 | 正常身份 → 开始 → 允许麦克风 → 完整 AI 回答；实际输出信号有效，用户确认应用中的声音可听见 |
| GemiGo 首页预览及探索流 | 同一应用能申请麦克风并播放；退出预览确实关闭连接、录音及播放；跨域登录在 iframe 受限时提供现有独立页面入口 |
| 连续会话 | 至少五轮回答、说话打断、静音/恢复、暂停 AudioContext 后恢复、挂断并再次通话均有效 |
| 手机 | 至少实际 iOS Safari 和 Android Chrome 验证一次完整通话；未获得实际设备时标为未验证，不用桌面缩放代替 |
| 授权与预算 | 无效/过期/重复票据、未启用应用、错误来源、额度耗尽被拒；并发申请不能超发；失败时不给客户端平台 Key |
| 生命周期 | 用户挂断、关页、网络中断、上游断开、额度/时长耗尽、服务发布均释放连接并按规则对账；确认后台没有遗留扣费连接 |
| 原有功能 | 中文/英语角色、音色、转写、打断、试听、恢复声音和 DeepSeek 文字模式保留；文字额度失败有反馈 |
| 发布与回滚 | 静态包无 Secrets；语音服务健康检查与回滚有效；应用仍使用可用版本，线上新路径完成真实 Qwen 验证 |

不保存原始音频或转写用于平台计量；日志只记录必要会话元数据、可诊断错误和用量。当前没有历史保存需求，不能因部署新增隐性内容留存。

## 方案审查与未决边界

本方案覆盖静态页面、实时语音、原有文字模式、平台身份、成本控制、嵌入预览和可听见的验收结果。反例检查：即使页面构建成功、Token 有 `voice:use`、供应商返回音频，也不能跳过应用许可、额度和实际播放证据。

当前可交付的是技术路线和工作划分。宿主资源/真实网络、可用预算具体值、实际手机设备与线上预览权限尚未核实；进入实现时将它们列为前置验证和发布门。平台赞助、登录试用与仅启用小伴是本方案的推荐策略，尚未得到用户定稿。design-document=required；实施计划在采用本方案后按实际宿主与额度合同细化。
