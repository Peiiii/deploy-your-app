# 应用列表加载态修复

## 目标与证据

用户切换应用类别时，应看到加载反馈，不能暂时出现“换一种语言／浏览全部语言”的空结果提示。线上 `/explore` 的 DOM 变更记录复现了约 303ms 的错误空态：切换类别清空列表，但 `isLoading` 要等 300ms debounce 后的 refresh 才置为 true。首页首屏也从空列表、loading=false 开始。

## 方案

复用现有卡片 skeleton。相比新增居中 spinner 或留白，它保留卡片布局且无需增加组件。首次请求默认处于加载中；探索页筛选发生实际变化时，由现有 store 在同一次更新中设置 loading=true、error=false，类别切换同时清空列表。搜索、标签的待请求阶段同样不能显示空态。重复选择保持 no-op，避免无新请求却永久 loading。现有 manager 负责请求完成后的状态，仍用当前筛选与 request ID 拒绝过期响应。首页 hook 只修正首次 loading 初值，原有类别切换已批量进入 skeleton。

不修改语言偏好、请求协议、排序与 pagination；真实空结果和失败仍显示既有提示与恢复操作。

## 验收

- 首页首次进入、探索页进入，以及类别／搜索／标签改变后，从待请求到请求完成不能出现语言空态；空列表显示现有 skeleton。
- 连续快速切换后，只接受最后一次筛选的响应；加载结束能显示对应应用。
- 无结果只在请求完成后出现；失败可重试；重复选择当前值不会卡住 loading。
- 前端类型检查、定向 lint、生产构建通过；浏览器记录类别切换期间 DOM 并检查实际 skeleton 渲染。
- 精确提交与普通推送，核对本地/远端 master 同步，使用现有 `deploy:pages` 发布并在线复验。

设计 Review：筛选更新和请求完成仍各归原 store/manager，未新增 owner 或抽象；重复值、过期响应和真实空结果边界已覆盖，无 findings。plan: not-required（单批局部修复）。
