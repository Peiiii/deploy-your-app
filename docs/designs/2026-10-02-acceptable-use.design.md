# 网站使用规范与发布提醒

用户要求（2026-10-02）：网站提醒禁止利用平台做违法的事情，并优化提示方式。项目定位是面向非专业用户的前端应用部署平台（README.md）。本次为 standard / feature，产品影响 L2；不改变部署协议或持久化。

## 方案

采用发布入口短提醒 + 独立中英文使用规范 + 现有私密反馈举报入口。仅页脚声明容易被忽略；强制弹窗/每次勾选增加发布阻力且没有服务端确认记录，因此采用常驻短提示。提示不代表内容已审核，也不宣称已经实现自动拦截。

在首页发布区域、新建发布按钮前、项目设置的再次部署按钮前复用同一 UsageNotice。首页底部提供使用规范、隐私政策、举报滥用链接。独立 `/acceptable-use` 页面沿用现有法律页面的独立入口模式，使用现有 i18n 和双语言按钮；提示链接开新页以保留用户编辑内容。隐私页面增加使用规范链接。

规范覆盖网站及通过 CLI/API 等方式部署的内容：遵守适用法律；禁止诈骗、钓鱼、恶意软件、非法交易、违法色情与儿童性剥削、侵权、未经授权公开个人信息、骚扰暴力和平台资源滥用。部署者负责内容及授权；平台可依证据与适用法律要求整改、限制服务或移除内容，严重情况可立即处理。不是通用服务条款或免责承诺。

举报复用 `/community` 的私密反馈（需登录），清楚说明操作步骤、应用完整 URL、问题描述、时间和必要证据；不要求密码或密钥，不制造未经确认的举报邮箱，不承诺处理时限。反馈仅举报者与 GemiGo 团队可见。新增匿名举报系统、自动审核和确认记录不属于本次提示需求。

参考结构：[Vercel AUP](https://vercel.com/legal/acceptable-use-policy)、[Cloudflare 举报说明](https://developers.cloudflare.com/fundamentals/reference/report-abuse/)。采用结构，不复制其特定商业限制。

## 验收与交付

1. 首页 → 看见短提醒 → 点击使用规范 → 阅读明确禁止事项与处理说明 → 返回原页面，已有输入不丢失；新发布/再次部署页面同样可读。
2. 无登录直接访问 `/acceptable-use#report` → 看见举报所需信息与登录要求 → 点击私密反馈 → 进入现有登录/反馈入口。复用既有反馈接口，不以测试举报污染线上收件箱。
3. 切换中文/英文，确认提醒与规范同步翻译；移动端无横向溢出，键盘链接可操作。

最小证据：frontend 类型检查、触达文件 ESLint、生产 build、实际浏览器验证提醒/规范/举报跳转及中英文移动布局、diff Review。按项目授权精确提交并同步 origin/master；提供包含改动的可用入口，线上生效需验证部署版本。plan: not-required，单批可闭环。

方案 Review（实现前）：目标、三个发布位置、独立法律入口、编辑内容保护和举报边界已覆盖；复用现有 owner，无新增状态或接口；无 finding，design-review: passed。
