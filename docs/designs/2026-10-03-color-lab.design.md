## 用户链路与视觉

浅色工作台、墨色文字、暗色实验画布，三束饱和 RGB 光作为主视觉，文字和控件可读。桌面左右布局，手机上下布局。第一屏可直接操作，知识解释跟随现象，避免读完长教程才能开始。

1. 自由混光：默认三束光全开 → 调整红/绿/蓝滑杆或预设 → 光束重叠区与混合色同步变化 → 看颜色值与简短解释 → 重置或继续试验。
2. 颜色挑战：点击挑战 → 看目标色与自己混合色 → 调节三束光 → 提交配方 → 不足时得到最需要调整的通道提示，达标后解锁下一关 → 完成五关得到结果 → 再来一轮。最后一关颜色固定便于可靠验收，重玩以相同规则重新开始；自由模式不计入挑战进度。
3. 分享：分享当前配方生成可复制的 URL 查询参数 → 另一个浏览器打开还原颜色 → 继续操作。剪贴板受限时显示可选择的链接，复制失败不误报成功。返回探索是明确的 GemiGo 入口。

交互状态由一份内存 state 拥有：mode、channels、challenge index、solved、attempts、completed。纯颜色模型服务 UI 与定向科学边界测试；不建第二套状态、平台 API 或持久进度系统。切换到挑战首关初始化，自由探索保留独立配方；挑战切到自由后能返回当前挑战，分享只分享可见配方，不分享通关凭证。

## 科学模型与来源

屏幕 RGB 加色模型：每通道 0～100 映射到 0～255；纯红、绿、蓝重叠用 screen 合成，因每束只有独立一个非零通道，交集与该组合的 RGB 输出一致。三个通道满值是白，零值是黑，红+绿是黄、红+蓝是品红、绿+蓝是青。操作量标为通道值，不冒充物理光功率测量。

匹配分数基于三个通道的归一化欧氏距离，称“色值接近度”，不称专业感知色差；达标规则为每通道偏差不超过 6/100。挑战目标先不显示 RGB 数值，完成后揭示配方。知识说明明确屏幕简化模型与颜料混色不同。

官方知识来源：[Exploratorium 加色混合](https://annex.exploratorium.edu/xref/phenomena/color_mixing_%28additive%29.html)、[MDN RGB](https://developer.mozilla.org/en-US/docs/Glossary/RGB)、[MDN color space](https://developer.mozilla.org/en-US/docs/Glossary/Color_space)。只参考概念，不复制网页、素材或表述。
