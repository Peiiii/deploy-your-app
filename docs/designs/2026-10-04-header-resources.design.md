## 问题与证据

用户先指出移动顶栏拥挤、点数入口不应公开，随后否定左上角的开发文档位置，要求认真比较候选，而非继续试着挪位置。

当前主线 `3fd34f7` 已把文档移到侧栏底部，修正手机顶栏挤压，并撤去顶栏钱包入口。该位置是现状，不是用户认可的最终设计。

- `frontend/src/components/header.tsx`：主题、语言、GitHub、帮助、通知、账户分别占位；GitHub 从 lg 显示，帮助/通知从 xl 显示。帮助目前直接打开 Crisp；通知没有点击处理，却展示红点。
- `frontend/src/components/sidebar/index.tsx`：开发文档单独占底部一行，折叠只保留图标。
- `developer-docs/pages/index.md`：文档面向账号、云数据、SDK 和点数接入，不等同于普通 HTML/ZIP 发布帮助；真实充值尚未开放。
- `frontend/src/routes.tsx` 与 `frontend/seo.mjs`：已有 HTML/ZIP 指南和反馈页面，可复用；侧栏反馈仍是独立的产品反馈入口。
- `frontend/src/components/popover.tsx`：已有弹层、外部点击/Esc/焦点关闭能力，可承担资源菜单。
- 产品定位尚在探索，当前能力不自动等于最终定位。此方案依据现有用户路径和页面内容，不假定所有用户都是 SDK 开发者，也不补写文档使用率。

## 候选比较

| 候选 | 用户路径与价值 | 代价与局限 | 适用条件 |
| --- | --- | --- | --- |
| A：右上角独立文档入口 | 全局一击进入；从左侧导航移出 | 继续增加常驻控件，手机容易拥挤；普通用户需辨认开发文档图标 | SDK 接入已成为多数用户高频任务 |
| B：侧栏底部独立文档入口（当前） | 桌面一击、手机打开侧栏后进入；成本最低 | 为单一专业资源常驻整行；没有处理帮助/GitHub/空通知的层级问题 | 只允许非常小的改动，或资源确实只有文档 |
| C：两端统一的「帮助与资源」菜单 | 顶栏一个稳定入口，展开后按普通帮助/开发资源区分；未登录同样可用 | 文档多一次点击；需要调整现有帮助按钮的语义和移动可见性 | 当前多种辅助资源并存、主任务仍是探索/发布/管理 |
| D：只放在相关功能附近 | SDK/API 设置旁直达相应文档，主导航最干净 | 未创建应用的人找不到入口，发布前学习接入的路径不完整；多个页面需要维护 | 作为全局入口之外的补充，不能单独覆盖现有需求 |

选择 C。最强替代是 B：实施便宜、入口直接，但只迁移了视觉占位，没有解决辅助入口分散。C 多一次点击换取清晰分组、稳定的跨设备位置和更少的常驻控件。若后续有真实证据表明文档为高频核心任务，再改选 A；本次不靠猜测冻结产品定位。

## 推荐交互

桌面和手机都由右上角的问号按钮进入同一份「帮助与资源」菜单，避免电脑在顶栏、手机另设侧栏资源菜单的两套路径。

- 顶栏左侧：手机菜单按钮；桌面继续由侧栏提供品牌与主导航，不新增装饰内容填空。
- 顶栏右侧：主题、语言、帮助与资源、账户；游客的登录仍遵循既有入口。手机语言控件显示图标，完整语言选择在原语言弹层中；桌面保留当前语言文字。手机操作目标至少 44×44px。
- GitHub 移入资源菜单，命名「项目源码」，避免与发布 GitHub 仓库混淆；撤去没有真实通知能力的按钮和红点，不实现通知系统。
- 侧栏底部撤去独立开发文档行，原账户入口和产品反馈导航保留。
- 钱包、充值不加入菜单，不修改支付、SDK 或文档站点中的财务机制。

菜单是一个浅层弹层，不新建帮助中心页面、不嵌套子菜单：

| 分组 | 条目 | 现有目标 |
| --- | --- | --- |
| 使用帮助 | 发布 HTML 指南 | `/guides/publish-html` |
| 使用帮助 | 发布 ZIP 指南 | `/guides/publish-zip` |
| 使用帮助 | 联系支持 | 当前 Crisp 对话 |
| 开发资源 | 开发者文档 | `https://docs.gemigo.io`，新标签页打开 |
| 开发资源 | 项目源码 | 当前 GitHub 仓库，新标签页打开 |

分组标题是说明文字，不是可点击菜单项。站内指南进入后关闭弹层并沿用语言。点击联系支持时关闭弹层，沿用现有支持动作与 analytics；未配置支持时给出可操作的反馈页入口，失败不能只在控制台记录。菜单支持键盘、Esc、外部点击；从打开状态触发站内路由变化时关闭。手机弹层限制在视口内，窄屏可采用顶栏下的宽面板，避免菜单又变成横向溢出的来源。

## 实现边界与复用

菜单内容与动作只由一个共享组件负责，安装在 Header；复用 Popover/IconButton 和既有路由，移走 Header 的帮助/源码动作和 Sidebar 的文档入口，不保留第二套独立资源清单。仅普通局部状态，无新 store、持久化、后台接口、第三方依赖或资源配置框架。Crisp 初始化仍由现有 CrispChat 负责。

后续源码主要范围为 Header、Sidebar、LanguageSwitcher、一个资源菜单组件及中英文文案。目前已有主题/语言持久化 owner 不变。真实通知、新帮助中心、文档内容重写、页面内文档推广及主导航重组均不属于本次实现。

## 黄金验收与证据要求

1. 手机游客打开首页：顶栏控件单行且不挤压；打开帮助与资源 → 看到普通帮助与开发资源两组 → 打开开发者文档 → 正确文档站点在新标签页出现 → 回到原页面继续浏览。无需登录，不出现钱包或充值入口。
