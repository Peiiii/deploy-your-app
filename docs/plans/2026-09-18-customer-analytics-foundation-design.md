# GemiGo 客户分析数据基座设计

## 决策

- 真人访问量以 Cloudflare Web Analytics RUM 的 `bot=0` 数据为唯一主口径；D1 页面计数只用于项目侧趋势和基础设施诊断。
- 项目表保存当前状态，新增不可变的部署尝试表保存每次上传/部署历史。项目来源只表示“最近一次部署来源”。
- `created_at`、`updated_at`、`last_success_at` 分离；`last_deployed` 仅作为兼容字段，今后只在成功部署时更新。
- 浏览量采集不保存 IP、完整 User-Agent 或完整 referrer。网关只上传带每日轮换的匿名哈希、粗粒度设备/浏览器、来源域名、UTM 和机器人分类。
- 产品事件保留 30 天明细，并在删除前写入 90 天日级聚合；部署事件以同一个 `flow_id` 串联浏览器开始、服务端受理/拒绝和最终结果。
- 超过 24 小时仍处于 `Building` 的项目和部署由每日任务标记失败，避免状态长期污染。

## 数据流

1. 主站浏览器生成匿名 visitor/session、来源与 UTM，并在部署请求中传递 `flow_id` 与客户端渠道。
2. API Worker 校验归属后创建部署尝试，持久化来源与项目当前来源，再代理到构建服务。
3. 构建 SSE 结束后更新部署尝试，并只在成功时更新项目的 `last_success_at`/`last_deployed`。
4. 应用网关对页面请求分类、匿名化和短窗口去重后写入 D1；Web Analytics 继续独立采集并作为真人流量主口径。
5. 管理 Worker 每日聚合产品事件、清理过期明细/去重键，并修复卡住的构建状态。

## 隐私与可靠性

- 匿名哈希使用 Worker Secret 的 HMAC-SHA-256，不把原始网络标识落库。
- 网关到 API 的采集接口使用共享 Secret，拒绝公开伪造。
- 所有新增表和列均使用幂等建表/迁移；发布顺序为数据库迁移、API、应用网关、管理 Worker、前端。
- 分析 Skill 只输出聚合数据，不输出邮箱、用户 ID、IP 或会话明细。
