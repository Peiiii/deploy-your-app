## 当前架构决定（取代 v1 的 /admin 与复用账号方案）
- admin.gemigo.io：独立 frontend build 与 Worker，独立登录凭据、签名会话、host-only cookie，不接受主站 session_id。复用纯数据合同和分析查询代码，不复用身份系统。
- 主站 API 仅负责采集；管理 Worker 负责授权查询与采集预算设置；分析使用独立表；账户 10 个 D1 名额已满（7406），复用 gemigo-projects 物理实例以保持免费，查询仅访问 product_events / analytics_settings / admin_sessions 等独立表。
- 共享包 product-analytics 是事件合同和数据查询的唯一 owner，包间通过公共入口使用。
- 明确语义事件与 route 模板，不采集表单内容、email、代码、secret、搜索词、原始 URL 或 IP。客户端时间与服务器接收时间分开。
- 浏览器优先把 <=20 条事件放入现有同源业务请求 header；无业务请求时 >=120 秒批量补报。每日每浏览器最多 6 次独立补报（包括关闭页），不以点击触发请求。不跨域捎带、不制造 preflight。
- 默认全站最多 2000 条事件/日，保留 30 天；每日预算耗尽停止写入并显示覆盖边界。D1 indexes 有写放大，预算不宣称等同 row writes。查询缓存及读取预算保护免费额度，管理 UI 不轮询。
- 页面、事件与结果区别展示；创建和邮箱登录、部署受理由服务器确认；部署完成为浏览器观测。漏斗使用同会话有序事件，缺失结果不推断失败。
- 作者身份使用公开昵称/handle；缺失信息使用通用身份占位并允许编辑，不替用户编造昵称或编号。中英文不改变用户名，不公开内部 ID，不把邮箱直接充当公开名称。

## 黄金验收链路
1. 打开管理站 → 独立登录 → 选择近 7 天 → 查看概览/排行 → 点击功能看事件 → 点击会话看路径 → 导出当前条件 CSV。测试身份、越权、空数据和预算耗尽也须清晰显示。
2. 主站浏览/搜索/预览/创建/部署 → 后台手动刷新 → 看到本次真实操作与服务器受理事件 → 展示成功率和漏斗计数；抓取采集请求计数，确认非逐点击。
3. 主站个人主页编辑公开昵称/用户名 → 公开卡片/主页中英文名称和头像一致 → 无邮箱及数据库 ID 泄漏到展示名称。
