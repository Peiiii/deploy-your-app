# GemiGo 双语社区入口设计

日期：2026-09-18

## 产品决策

当前用户量较少，不建设公开站内信息流。社区交流按用户所在生态拆分：国内用户进入微信群，海外用户进入 Discord；产品反馈仍统一提交到 GemiGo，避免两个群里的需求彼此割裂。

页面不使用 IP 定位。中文界面优先展示微信，英文界面优先展示 Discord，但两个入口始终可见，兼容海外华人、在华外国用户和 VPN 场景。

## 页面结构

1. 顶部说明 GemiGo 社区的价值：直接交流、提前体验、共同决定产品方向。
2. 两张社群卡片：微信群显示二维码，Discord 显示外链按钮。
3. 统一反馈区：登录用户提交建议、问题或疑问，提交后进入同一反馈池。
4. 管理员反馈收件箱：只有管理员可见，用于阅读反馈、评论和更新状态；普通用户不看到冷清的信息流。

## 配置方式

- `VITE_COMMUNITY_WECHAT_QR_URL`：微信群二维码图片 URL，可使用站内静态资源路径或 HTTPS 地址。
- `VITE_COMMUNITY_DISCORD_INVITE_URL`：Discord 邀请 URL。

配置缺失时页面显示明确的“待配置”状态，不渲染坏图片或伪造邀请链接。

## 架构与验证

继续复用现有 Community API、D1 数据模型、登录态和反馈发布器。前端新增集中式社群配置和入口卡片，并把反馈列表降级为管理员专属收件箱。发布前执行 lint、全仓 type check、前端生产构建，并在中文、英文、桌面端、移动端和深色模式下做视觉检查。
