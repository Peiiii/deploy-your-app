# 项目缩略图占位设计修复

## 问题

中央缩略图服务在真实截图尚未生成时返回固定蓝紫渐变 SVG。它只读取 URL slug 的首字符，因此泰文等无法直接作为子域名的项目通常使用 `app-*` slug，最终全部显示成 `A`，不同项目的背景也完全相同。这个服务端 SVG 会以 HTTP 200 加载，前端原有的“按项目着色、标题首字母倾斜”兜底因而不会出现。

## 决策

保留中央 SVG 占位方案，以维持一次请求、极小体积和零布局偏移；前端在缩略图 URL 中附带项目名称与稳定项目 ID。Worker 使用 Unicode 项目名的首个字符作为视觉标记，以项目 ID 做确定性哈希，从六组渐变中选择颜色，并恢复 `-12°` 的倾斜大字设计。

参数只影响缺图时的视觉占位。真实 WebP 已存在或生成后，仍由相同端点返回，图片压缩、懒加载、缓存和自动截图链路均保持不变。名称写入 SVG 前必须 XML 转义，避免生成无效标记或注入内容。

## 验收标准

- 泰文、中文和英文项目均显示各自名称的首个 Unicode 字符。
- 不同项目 ID 稳定映射到多组渐变，而不是固定紫色。
- 大字恢复 `-12°` 倾斜视觉。
- 真实 WebP、缺图后台生成、100KB 上限与缓存策略不退化。
- 缩略图专项测试、lint、type check 和生产构建全部通过，并在生产页面视觉验收。
